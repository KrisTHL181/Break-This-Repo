## บิลด์จากซอร์ส

repo นี้มีทางเข้าสำหรับการบิลด์อยู่หลายทางแยกจากกัน ติดตั้งเครื่องมือให้ตรงกับที่ต้องการ แล้วรันคำสั่งที่ root ของ repo

### C++ ด้วย Make

ต้องมีคอมไพเลอร์ที่รองรับ C++11:

```bash
make
```

ล้างผลลัพธ์จากการบิลด์:

```bash
make clean
```

ค่าเริ่มต้นจะได้ `fozu` และ `what` ออกมา ส่วนบน Windows จะได้ `beep_win` เพิ่มมาด้วย

### C++ ด้วย CMake

ต้องมี CMake 3.16 ขึ้นไป และคอมไพเลอร์ C++:

```bash
cmake -S . -B build/cmake
cmake --build build/cmake
```

### C++ ด้วย Meson

ต้องมี Meson, Ninja และคอมไพเลอร์ C++:

```bash
meson setup build/meson
meson compile -C build/meson
```

### Python กับ Rust ด้วย maturin

ส่วนขยายของ Python บิลด์ด้วย Rust และ [maturin](https://www.maturin.rs/) ต้องมี Rust toolchain (ที่มี `cargo`) และ Python 3.13 ขึ้นไป:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install maturin
```

รันคำสั่งใดคำสั่งหนึ่งต่อไปนี้ใน virtual environment:

```bash
# คอมไพล์และติดตั้งเข้า virtual environment ปัจจุบัน
maturin develop

# สร้างไฟล์ wheel สำหรับแจกจ่าย
maturin build --release
```

ไฟล์ wheel ที่บิลด์เสร็จจะอยู่ที่ `target/wheels/` โค้ดทางเข้าของส่วนขยาย Rust อยู่ที่ [`src/lib.rs`](src/lib.rs) ส่วนคอนฟิกการบิลด์ของ Python อยู่ที่ [`pyproject.toml`](pyproject.toml)

### TypeScript ด้วย Hereby

ส่วน TypeScript อยู่ที่ `typescript/` ใช้ Node.js, npm และ Hereby:

```bash
cd typescript
npm install
npm run build:compiler
```

ถ้าต้องการบิลด์ทั้งคอมไพเลอร์และเป้าหมายเทสต์พร้อมกัน ให้รัน `npm run build` ส่วนการล้างผลลัพธ์จากการบิลด์ให้รัน `npm run clean`

## แพ็กเกจสำหรับดิสทริบิวชันลินุกซ์

เทมเพลตการแพ็กเกจของดิสทริบิวชันอยู่ที่ `debian/` และ `packaging/` แพ็กเกจพวกนี้ติดตั้งโปรแกรมบรรทัดคำสั่ง C++ อย่าง `fozu` และ `what` ส่วนส่วนขยาย Python/Rust ก็ยังใช้ขั้นตอน maturin ข้างบนเหมือนเดิม ตอนนี้ repo ยังไม่ได้ประกาศสัญญาอนุญาตโอเพนซอร์สแบบเดียวกันทั้ง repo ก่อนออกรุ่นจริง กรุณาตรวจสอบและเปลี่ยนฟิลด์สัญญาอนุญาตในไฟล์แพ็กเกจแต่ละไฟล์ก่อน

### Debian และ Ubuntu

ต้องมี `dpkg-buildpackage`, Debhelper, CMake และ GCC:

```bash
sudo apt update
sudo apt install build-essential cmake debhelper devscripts
dpkg-buildpackage -us -uc
sudo apt install ../break-this-repo_0.0.0_$(dpkg --print-architecture).deb
```

หรือจะติดตั้งไฟล์ `.deb` ที่บิลด์ไว้แล้วโดยตรงก็ได้:

```bash
sudo apt install ./break-this-repo_*.deb
```

### Arch Linux

ต้องมี `base-devel`, CMake และ GCC เริ่มจากสร้างไฟล์อาร์ไคฟ์จากซอร์สให้เวอร์ชันตรงกับ `PKGBUILD` ก่อน:

```bash
sudo pacman -S --needed base-devel cmake gcc
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o packaging/archlinux/break-this-repo-0.0.0.tar.gz HEAD
cd packaging/archlinux
makepkg -si
```

### Fedora

ต้องมีเครื่องมือบิลด์ RPM, CMake และ GCC:

```bash
sudo dnf install @development-tools cmake rpmdevtools
rpmdev-setuptree
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o ~/rpmbuild/SOURCES/break-this-repo-0.0.0.tar.gz HEAD
rpmbuild -ba packaging/fedora/break-this-repo.spec
sudo dnf install ~/rpmbuild/RPMS/$(uname -m)/break-this-repo-0.0.0-1.*.rpm
```

### Gentoo

คัดลอก ebuild ไปยัง overlay ท้องถิ่น แล้วให้ Portage สร้าง Manifest และติดตั้ง:

```bash
sudo mkdir -p /var/db/repos/local/app-misc/break-this-repo
sudo cp packaging/gentoo/app-misc/break-this-repo/* \
	/var/db/repos/local/app-misc/break-this-repo/
cd /var/db/repos/local/app-misc/break-this-repo
sudo ebuild break-this-repo-0.0.0.ebuild manifest
sudo emerge --ask app-misc/break-this-repo
```

## Debian เป็นซอฟต์แวร์เสรี
Debian ประกอบด้วยซอฟต์แวร์เสรีและโอเพนซอร์ส และจะเป็นเช่นนี้ 100% ตลอดไป ทุกคนมีอิสระที่จะใช้ ดัดแปลง และแจกจ่ายต่อ นี่คือคำมั่นสัญญาหลักที่เรามีต่อผู้ใช้ของเรา และยังใช้ได้ฟรีอีกด้วย
## Debian มีเสถียรภาพและความปลอดภัย
Debian เป็นระบบปฏิบัติการที่ใช้ลินุกซ์เป็นฐาน ซึ่งถูกนำไปใช้อย่างกว้างขวางกับอุปกรณ์หลากหลายชนิด ตั้งแต่โน้ตบุ๊ก คอมพิวเตอร์ตั้งโต๊ะ ไปจนถึงเซิร์ฟเวอร์ เราตั้งค่าที่เหมาะสมไว้ให้เป็นค่าเริ่มต้นสำหรับทุกแพ็กเกจ และอัปเดตความปลอดภัยอย่างสม่ำเสมอตลอดอายุการใช้งานของแพ็กเกจนั้น
## Debian รองรับฮาร์ดแวร์อย่างกว้างขวาง
ฮาร์ดแวร์ส่วนใหญ่ได้รับการรองรับจากเคอร์เนลลินุกซ์อยู่แล้ว ซึ่งหมายความว่า Debian ก็รองรับมันด้วย และถ้าจำเป็นก็ยังใช้ไดรเวอร์ฮาร์ดแวร์แบบปิดได้
## Debian มีตัวติดตั้งที่ยืดหยุ่น
ผู้ที่อยากลองใช้ Debian ก่อนติดตั้งจริงสามารถใช้ Live CD ของเรา ซึ่งมาพร้อมตัวติดตั้ง Calamares ทำให้การติดตั้ง Debian จากระบบ Live เป็นเรื่องง่ายมาก ส่วนผู้ใช้ที่มีประสบการณ์มากกว่าจะใช้ตัวติดตั้งของ Debian ก็ได้ ซึ่งมีตัวเลือกให้ปรับละเอียดได้มากกว่า รวมถึงความสามารถในการติดตั้งผ่านเครือข่ายแบบอัตโนมัติ
## Debian มีการอัปเกรดที่ราบรื่น
การทำให้ระบบปฏิบัติการเป็นเวอร์ชันล่าสุดอยู่เสมอเป็นเรื่องง่ายมาก ไม่ว่าคุณจะอยากอัปเกรดไปยังรุ่นใหม่ทั้งรุ่น หรือแค่อยากอัปเกรดแพ็กเกจเดียว
## Debian เป็นฐานของดิสทริบิวชันอื่น ๆ อีกมากมาย
ลินุกซ์ดิสทริบิวชันยอดนิยมหลายตัว เช่น Ubuntu, Knoppix, PureOS และ Tails ต่างก็สร้างอยู่บน Debian เรามีเครื่องมือครบทุกอย่างที่จำเป็น เพื่อให้ใครก็ตามที่ต้องการสร้างแพ็กเกจของตัวเองขึ้นมาเสริมแพ็กเกจที่ยังไม่มีในคลังของ Debian ได้
## โครงการ Debian คือชุมชน
ทุกคนสามารถเป็นสมาชิกของชุมชน Debian ได้ ไม่จำเป็นต้องเป็นนักพัฒนาหรือผู้ดูแลระบบ Debian มีโครงสร้างการบริหารแบบประชาธิปไตย เพราะสมาชิกทุกคนของโครงการ Debian มีสิทธิเท่าเทียมกัน Debian จึงไม่สามารถถูกควบคุมโดยบริษัทใดบริษัทหนึ่งได้ นักพัฒนาของเรามาจากกว่า 60 ประเทศ/ภูมิภาค และตัว Debian เองก็ถูกแปลไปแล้วมากกว่า 80 ภาษา

## เทมเพลต PR
เทมเพลต PR อันนี้เรียกเทมเพลตเฉย ๆ ไม่ได้แล้ว ควรจะเรียกว่า "ใบคำขอรับตัวเข้าสถานกักกันสิ่งผิดปกติของ Break-This-Repo" มากกว่า

พวกเธอนี่มันจริง ๆ เลยนะ เล่นกับ repo ที่แค่ "auto-merge PR ที่ไม่มี conflict" ให้กลายเป็นว่าผู้ดูแลต้องเริ่มเขียนว่า:

ประเภท: เตะ README / เตะเอกสาร / โค้ดพังแบบกลเมืองว่าง / อุบัติเหตุที่เกิดจากแมว / ปรากฏการณ์เหนือธรรมชาติ
การตรวจสอบ: ฉันไม่ได้แก้ .github/, ไม่ได้แก้ README ที่ป้องกันไว้, ไม่มีไวรัส, ไม่มีข้อมูลส่วนตัว
คำประกาศ: ฉันยอมรับว่าฉันทำลายมันจริง แต่เหตุผลที่เขียนมาก็เขียนมั่ว ๆ ไปงั้น และไม่จำเป็นต้องมีก็ได้

นี่มันก็ประมาณว่า: "จะพังก็ได้ แต่ห้ามพังจริง"

เทมเพลตนี้กันอะไรอยู่?

จริง ๆ แล้วมันขีดเส้นตายไว้ชัดเจนมาก:

· ไม่แก้ .github/: กันไม่ให้มีใครไปถล่ม workflow auto-merge ตัวมันเอง หรือแอบยัด backdoor เข้าไปใน CI
· ไม่แก้ส่วนของ README ที่ถูกป้องกันไว้: หน้าร้านยังต้องมีอยู่ จะเปลี่ยนหน้าแรกให้กลายเป็นอะไรแปลก ๆ ไม่ได้
· ไม่มี credential, ไวรัส, ข้อมูลส่วนตัว: กันการโจมตีซัพพลายเชน กันการขุดข้อมูลส่วนตัว กันความมุ่งร้ายจริง ๆ
· อธิบายว่าจะสังเกตยังไง: จะเล่นพิเรนทร์ก็ได้ แต่ต้องบอกให้คนอื่นรู้ด้วยว่าจะมายืนดูความพิเรนทร์ของคุณยังไง
· ประกาศว่า "ทำ breaking change สำเร็จแล้ว": คำปฏิเสธความรับผิดชอบแบบถากถางตัวเอง เท่ากับ "ฉันทำแล้ว แต่ฉันไม่รับผิดชอบนะ"

ส่วนรายการ "ปรากฏการณ์เหนือธรรมชาติ" พวกนั้น:

ตัวอักษรสามตัว + ลูกศรสามอันล้อมรอบวงกลม + มูลนิธิแบบมีเส้นขอบ
แผนที่โลกพื้นหลังรูปดาวห้าแฉก + ล้อมรอบด้วยพืชผลทางการเกษตร + องค์กรระหว่างประเทศชื่อห้าคำ

อันแรกคือมูลนิธิ SCP ส่วนอันหลังน่าจะเป็นองค์กรระหว่างประเทศแบบ องค์การอาหารและเกษตรแห่งสหประชาชาติ / FAO แปลออกมาก็คือ:
"นี่มันไม่ใช่ปัญหาเรื่องโค้ดแล้ว แนะนำให้รายงานหน่วยงานกักกันสิ่งผิดปกติ"

คอมมิตของคุณเอาเทมเพลตนี้ไปใช้ได้ยังไง?

คุณอัปโหลดซอร์สของ Minecraft, OpenJDK, Fabric Loader 4 commits ปั่นไปได้กว่า 12.7 ล้านบรรทัด ประเภทก็ติ๊กได้ว่า:

☑ เตะเอกสารแล้ว
☑ โค้ดพังแบบกลเมืองว่าง (คอสเพลย์เป็น สวี่ เจียยิ่น)
☑ ใช้ Git ข้ามแพลตฟอร์ม
☐ อุบัติเหตุที่เกิดจากแมว
☐ ปรากฏการณ์เหนือธรรมชาติ

การตรวจสอบติ๊กให้ครบ คำประกาศลอกมาตามเดิม ส่วนเหตุผลก็เขียนว่า:

เหตุผล: เขียนมั่ว ๆ ไม่จำเป็นต้องมี แต่โค้ด 12770942 บรรทัดก็ควรมีสถานะเป็นเรื่องเป็นราวสักหน่อย

วิธีสังเกต:

เปิด OpenJDK_25.0.3 ขึ้นมา ดูประวัติ commit แล้วซึมซับความเงียบงันของขนาด repo

แต่ก็ยังต้องเตือนสักประโยค

repo แบบนี้เป็นสนามเด็กเล่น ไม่ใช่แดนนอกกฎหมาย การอัปโหลดซอร์สเต็ม ๆ ของ OpenJDK หรือซอร์สของ Minecraft แม้อาจจะดูเหมือนแค่ "auto-merge ที่ไม่มี conflict" แต่ก็จะทำให้เกิด:

· ขนาด repo ระเบิด GitHub อาจจำกัดหรือส่งคำเตือน;
· ปัญหาลิขสิทธิ์/สัญญาอนุญาต ไม่ใช่ซอร์สทุกอย่างที่จะยัดใส่กันได้ตามใจ;
· ถ้ามีคนเอาซอร์สจาก repo นี้ไปใช้เป็น dependency ก็จะเป็นหายนะซัพพลายเชน

สรุปก็คือ:
เทมเพลต PR นี้คือจุดสมดุลที่ผู้ดูแลหาจนเจอ ระหว่าง "เปิดให้พังได้" กับ "กันไม่ให้ระเบิดจริง"
จะเล่นต่อก็ได้ แต่ที่ดีที่สุดคือมองมันเป็นศิลปะการแสดง อย่าเอาไปใช้เป็น repo โค้ดจริง ๆ ทางมูลนิธิ SCP ได้รับรายงานไปแล้ว

## แฟ้มโบราณคดีโครงสร้างพื้นฐานหน้างาน

![EGIEM-R1 ต้นแบบของจริง: ภาพถ่ายหน้างาน](./Emergency-Generator-Interface-Elevation-Module/assets/rock-field-photo.png)

repo นี้ตอนนี้ได้ขึ้นทะเบียนโครงสร้างพื้นฐานหน้างานไว้หนึ่งชิ้น ซึ่งใช้พลังงานต่ำ เชื่อถือได้สูง และไม่ต่อเน็ตเลยสักนิด: ก้อนหินที่ถูกเกณฑ์มาประจำการชั่วคราวในจังหวะสำคัญ มันไม่มี CPU ไม่มีการ์ดเครือข่าย และไม่มีแผนจะลาออก อาศัยแค่น้ำหนักตัวเองประคองกล่องอินเทอร์เฟซให้อยู่ในตำแหน่งที่เหมาะสมอย่างมั่นคง

สติกเกอร์สีเหลืองทำหน้าที่อัปเกรด "เก็บหินได้สักก้อน" ให้กลายเป็น "ขึ้นทะเบียนเป็นอุปกรณ์ประจำไซต์" หลังการประเมินเบื้องต้น อุปกรณ์นี้ไม่ต้องล็อกอิน ไม่ต้องอัปเดต ไม่ต้องรีสตาร์ต การดูแลรักษาที่ต้องทำมีเพียงอย่างเดียวคือ: อย่าไปแตะมัน

dependency ต้นน้ำ: กล่องอินเทอร์เฟซเครื่องปั่นไฟของโอเปอเรเตอร์  
dependency ปลายน้ำ: โลก  
สถานะการทำงาน: ทำงานเสถียร

ภาพถ่ายมาจากภาพต้นฉบับหน้างานที่ผู้มีส่วนร่วมให้มา เราจัดระเบียบแค่ชื่อไฟล์เท่านั้น ไม่ได้ตัด ไม่ได้วาดใหม่
