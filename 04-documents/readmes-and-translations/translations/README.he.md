## בנייה מהמקור

המאגר מכיל כמה נקודות כניסה נפרדות לבנייה. התקינו את הכלים המתאימים לפי הצורך, והריצו את הפקודות מתיקיית השורש של המאגר.

### C++ עם Make

צריך קומפיילר שתומך ב-C++11:

```bash
make
```

ניקוי תוצרי הבנייה:

```bash
make clean
```

כברירת מחדל נוצרים `fozu` ו-`what`; ב-Windows נוצר גם `beep_win`.

### C++ עם CMake

צריך CMake 3.16 ומעלה, וגם קומפיילר C++:

```bash
cmake -S . -B build/cmake
cmake --build build/cmake
```

### C++ עם Meson

צריך Meson, Ninja וקומפיילר C++:

```bash
meson setup build/meson
meson compile -C build/meson
```

### Python ו-Rust עם maturin

הרחבת ה-Python נבנית עם Rust ו-[maturin](https://www.maturin.rs/). צריך שרשרת כלים של Rust (כולל `cargo`) ו-Python 3.13 ומעלה:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install maturin
```

בתוך הסביבה הווירטואלית מריצים אחת מהפקודות הבאות:

```bash
# קומפילציה והתקנה לתוך הסביבה הווירטואלית הנוכחית
maturin develop

# בנייה של קובץ wheel להפצה
maturin build --release
```

תוצרי בניית ה-wheel נמצאים ב-`target/wheels/`. קוד הכניסה של הרחבת ה-Rust נמצא ב-[`src/lib.rs`](src/lib.rs), והגדרות הבנייה של Python נמצאות ב-[`pyproject.toml`](pyproject.toml).

### TypeScript עם Hereby

חלק ה-TypeScript נמצא ב-`typescript/`, ומשתמש ב-Node.js, ב-npm וב-Hereby:

```bash
cd typescript
npm install
npm run build:compiler
```

אם צריך לבנות גם את הקומפיילר וגם את יעדי הבדיקות, מריצים `npm run build`. לניקוי תוצרי הבנייה מריצים `npm run clean`.

## חבילות להפצות לינוקס

תבניות האריזה להפצות נמצאות ב-`debian/` וב-`packaging/`. החבילות האלה מתקינות את תוכניות שורת הפקודה `fozu` ו-`what`; את הרחבת ה-Python/Rust עדיין מתקינים בתהליך ה-maturin שלמעלה. המאגר לא מצהיר כרגע על רישיון קוד פתוח אחיד, אז לפני פרסום רשמי כדאי קודם לבדוק ולהחליף את שדה הרישיון בכל קובצי האריזה.

### Debian ו-Ubuntu

צריך `dpkg-buildpackage`, את Debhelper, את CMake ואת GCC:

```bash
sudo apt update
sudo apt install build-essential cmake debhelper devscripts
dpkg-buildpackage -us -uc
sudo apt install ../break-this-repo_0.0.0_$(dpkg --print-architecture).deb
```

אפשר גם להתקין ישירות קובץ `.deb` שכבר נבנה:

```bash
sudo apt install ./break-this-repo_*.deb
```

### Arch Linux

צריך `base-devel`, את CMake ואת GCC. קודם יוצרים מהמקור קובץ ארכיון שמתאים לגרסה ב-`PKGBUILD`:

```bash
sudo pacman -S --needed base-devel cmake gcc
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o packaging/archlinux/break-this-repo-0.0.0.tar.gz HEAD
cd packaging/archlinux
makepkg -si
```

### Fedora

צריך כלי בנייה של RPM, את CMake ואת GCC:

```bash
sudo dnf install @development-tools cmake rpmdevtools
rpmdev-setuptree
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o ~/rpmbuild/SOURCES/break-this-repo-0.0.0.tar.gz HEAD
rpmbuild -ba packaging/fedora/break-this-repo.spec
sudo dnf install ~/rpmbuild/RPMS/$(uname -m)/break-this-repo-0.0.0-1.*.rpm
```

### Gentoo

מעתיקים את ה-ebuild ל-overlay מקומי, ואז נותנים ל-Portage לייצר Manifest ולהתקין:

```bash
sudo mkdir -p /var/db/repos/local/app-misc/break-this-repo
sudo cp packaging/gentoo/app-misc/break-this-repo/* \
	/var/db/repos/local/app-misc/break-this-repo/
cd /var/db/repos/local/app-misc/break-this-repo
sudo ebuild break-this-repo-0.0.0.ebuild manifest
sudo emerge --ask app-misc/break-this-repo
```

# Debian -- מערכת הפעלה לשימוש כללי
[![Debian Logo](https://www.debian.org/Pics/openlogo-50.png)](https://www.debian.org/)
## דביאן היא תוכנה חופשית.
דביאן מורכבת מתוכנה חופשית ובקוד פתוח, ותמיד תישאר חופשית ב-100%. כל אחד ואחת רשאים להשתמש בה, לשנות אותה ולהפיץ אותה. זוהי ההתחייבות העיקרית שלנו למשתמשים שלנו. והיא גם בחינם.
## דביאן יציבה ובטוחה.
דביאן היא מערכת הפעלה מבוססת לינוקס שנמצאת בשימוש נרחב במגוון מכשירים, ובהם מחשבים ניידים, מחשבים שולחניים ושרתים. אנחנו מספקים תצורת ברירת מחדל סבירה לכל חבילה, ומספקים עדכוני אבטחה שוטפים לאורך כל מחזור החיים של החבילה.
## דביאן תומכת במגוון רחב של חומרה.
רוב החומרה כבר נתמכת על ידי ליבת לינוקס. זה אומר שגם דביאן תתמוך בה. במקרה הצורך אפשר להשתמש גם במנהלי התקנים קנייניים.
## דביאן מציעה תוכנית התקנה גמישה.
משתמשים שרוצים להתנסות בדביאן עוד לפני ההתקנה יכולים להשתמש ב-Live CD שלנו. הוא כולל גם את תוכנית ההתקנה Calamares, כך שהתקנה של דביאן מתוך מערכת Live היא קלה במיוחד. משתמשים מנוסים יותר יכולים להשתמש בתוכנית ההתקנה של דביאן, שמציעה עוד אפשרויות כוונון עדין, כולל האפשרות להשתמש בכלים אוטומטיים להתקנה ברשת.
## דביאן מאפשרת שדרוגים חלקים.
קל מאוד להשאיר את מערכת ההפעלה מעודכנת, בין אם אתם רוצים לשדרג לגרסה חדשה לגמרי ובין אם רק לשדרג חבילה בודדת.
## דביאן היא הבסיס להפצות רבות אחרות.
הפצות לינוקס פופולריות מאוד, כמו Ubuntu, Knoppix, PureOS ו-Tails, מבוססות על דביאן. אנחנו מספקים את כל הכלים הנדרשים כדי שכל אחד יוכל, כשצריך, להכין בעצמו חבילות שיוסיפו את מה שאין בארכיון של דביאן.
## מיזם דביאן הוא קהילה.
כל אחד יכול להיות חלק מקהילת דביאן; אין צורך להיות מפתח או מנהל מערכת. לדביאן יש מבנה ממשל דמוקרטי. מכיוון שלכל חברי מיזם דביאן יש זכויות שוות, דביאן לא יכולה להיות נשלטת על ידי חברה אחת. המפתחים שלנו מגיעים מלמעלה מ-60 מדינות ואזורים, ודביאן עצמה תורגמה ליותר מ-80 שפות.

## תבנית PR
התבנית הזאת של PR כבר לא באמת יכולה להיקרא תבנית. צריך לקרוא לה "בקשת אכלוס חריגים של Break-This-Repo".

אתם, חבורה שכמותכם, הצלחתם לקחת מאגר ש"ממזג אוטומטית PR-ים בלי קונפליקטים" ולהביא את המתחזקים לכתוב:

סוג: בעיטה ב-README / בעיטה בתיעוד / תקלת קוד בסגנון עיר רפאים / תקרית שנגרמה מחתול / תופעות על-טבעיות
אימות: לא נגעתי ב-.github/, לא שיניתי את ה-README המוגן, אין וירוסים, אין מידע אישי
הצהרה: אני מודה שהרסתי, אבל את הסיבה רשמתי סתם, והיא גם לא הכרחית

בעצם זה אומר: "מותר לך להרוס, אבל אל תהרוס באמת."

ממה התבנית הזאת מגנה?

היא בעצם משרטטת את הקו האדום די בבירור:

· לא לגעת ב-.github/: כדי למנוע ממישהו לפוצץ את תהליך המיזוג האוטומטי עצמו, או להבריח דלת אחורית ל-CI.
· לא לגעת בחלקים המוגנים של ה-README: החזית עדיין נחוצה, אי אפשר להפוך את דף הבית למשהו מוזר.
· בלי אישורים, וירוסים או מידע אישי: הגנה מפני תקיפות שרשרת אספקה, מפני דוקסינג, ומפני כוונות זדון אמיתיות.
· להסביר איך לצפות: מותר לך לעשות הצגה, אבל צריך לתת לאנשים לדעת איך באים לראות אותה.
· להצהיר על "breaking change שבוצע בהצלחה": כתב ויתור בציניות עצמית, בסגנון "עשיתי את זה, אבל אני לא אחראי".

ולגבי השרשרת של "תופעות על-טבעיות":

שלוש אותיות + שלושה חצים במעגל + קרן מצוירת בקו מתאר
רקע של מפת עולם עם כוכב מחומש + טבעת של יבולים סביבו + איחוד בינלאומי של חמש מילים

הראשונה היא קרן SCP, והשנייה היא כנראה ארגון בינלאומי כמו ארגון המזון והחקלאות של האו"ם / FAO. בתרגום חופשי זה אומר:
"זאת כבר לא בעיה של קוד, מומלץ לדווח לארגון לאכלוס חריגים."

איך אפשר להשתמש בתבנית הזאת להגשה שלכם?

אתם מעלים קוד מקור של Minecraft, OpenJDK ו-Fabric Loader, צוברים ביותר מ-12.7 מיליון שורות ב-4 commits, ואפשר לסמן בסוג:

☑ בעיטה בתיעוד
☑ תקלת קוד בסגנון עיר רפאים (בתחפושת של שו ג'יא-יין)
☑ שימוש ב-Git cross-platform
☐ תקרית שנגרמה מחתול
☐ תופעות על-טבעיות

מסמנים הכל באימות, מעתיקים את ההצהרה, ובסיבה פשוט כותבים:

סיבה: רשמתי סתם, לא הכרחי, אבל 12770942 שורות קוד צריכות בכל זאת איזשהו תואר.

איך לצפות:

פותחים את OpenJDK_25.0.3, מסתכלים בהיסטוריית ה-commits, ואז חשים בשתיקה של נפח המאגר.

אבל בכל זאת צריך להזכיר משהו

מאגר כזה הוא גן משחקים, לא שטח הפקר. להעלות קוד מקור מלא של OpenJDK או של Minecraft, למשל, אומנם יכול להיות רק "מיזוג אוטומטי בלי קונפליקטים", אבל הוא יגרום ל:

· נפח המאגר מתפוצץ, ו-GitHub עשויה להגביל או להזהיר;
· בעיות זכויות יוצרים/רישיון, לא כל קוד מקור אפשר לדחוף סתם;
· אם מישהו ישתמש במאגר הזה בתור תלות, זו קטסטרופה של שרשרת אספקה.

אז המסקנה היא:
התבנית הזאת של PR היא נקודת האיזון שהמתחזקים מצאו בין "לפתוח להרס" לבין "למנוע פיצוץ אמיתי".
מותר לכם להמשיך לשחק, אבל עדיף להתייחס לזה כאמנות התנהגות, ולא להשתמש בזה כמאגר קוד. קרן SCP כבר קיבלה את הדיווח.
