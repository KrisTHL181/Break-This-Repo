## 소스에서 빌드하기

저장소에는 서로 독립적인 빌드 진입점이 여러 개 있습니다. 필요한 도구를 설치하고, 저장소 루트에서 명령을 실행하세요.

### Make로 빌드하는 C++

C++11을 지원하는 컴파일러가 필요합니다:

```bash
make
```

빌드 산출물 정리:

```bash
make clean
```

기본적으로 `fozu`와 `what`이 생성되고, Windows에서는 `beep_win`도 함께 생성됩니다.

### CMake로 빌드하는 C++

CMake 3.16 이상과 C++ 컴파일러가 필요합니다:

```bash
cmake -S . -B build/cmake
cmake --build build/cmake
```

### Meson으로 빌드하는 C++

Meson, Ninja, C++ 컴파일러가 필요합니다:

```bash
meson setup build/meson
meson compile -C build/meson
```

### maturin으로 빌드하는 Python과 Rust

Python 확장은 Rust와 [maturin](https://www.maturin.rs/)으로 빌드합니다. Rust 툴체인(`cargo` 포함)과 Python 3.13 이상이 필요합니다:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install maturin
```

가상 환경에서 다음 명령 중 하나를 실행하세요:

```bash
# 컴파일해서 현재 가상 환경에 설치
maturin develop

# 배포용 wheel 파일 빌드
maturin build --release
```

wheel 빌드 산출물은 `target/wheels/`에 있습니다. Rust 확장의 진입 코드는 [`src/lib.rs`](src/lib.rs)에, Python 빌드 설정은 [`pyproject.toml`](pyproject.toml)에 있습니다.

### Hereby로 빌드하는 TypeScript

TypeScript 부분은 `typescript/`에 있으며, Node.js, npm, Hereby를 사용합니다:

```bash
cd typescript
npm install
npm run build:compiler
```

컴파일러와 테스트 타깃을 함께 빌드하려면 `npm run build`를 실행하세요. 빌드 산출물을 정리하려면 `npm run clean`을 실행하면 됩니다.

## 중요한 추가 사항

컴파일할 때는 최소 114GB의 메모리와 514GB 이상의 저장 공간을 준비하고, 1919810코어 CPU를 10GHz로 돌려야 합니다

## 리눅스 배포판 패키지

배포판 패키징 템플릿은 `debian/`과 `packaging/`에 있습니다. 이 패키지들은 C++ 명령줄 프로그램 `fozu`와 `what`을 설치합니다. Python/Rust 확장은 위의 maturin 절차를 그대로 사용하세요. 이 저장소는 아직 통일된 오픈 소스 라이선스를 명시하고 있지 않으니, 정식 배포 전에 각 패키징 파일의 라이선스 필드를 확인해서 교체하시기 바랍니다.

### Debian과 Ubuntu

`dpkg-buildpackage`, Debhelper, CMake, GCC가 필요합니다:

```bash
sudo apt update
sudo apt install build-essential cmake debhelper devscripts
dpkg-buildpackage -us -uc
sudo apt install ../break-this-repo_0.0.0_$(dpkg --print-architecture).deb
```

이미 빌드된 `.deb` 파일을 바로 설치할 수도 있습니다:

```bash
sudo apt install ./break-this-repo_*.deb
```

### Arch Linux

`base-devel`, CMake, GCC가 필요합니다. 먼저 소스에서 `PKGBUILD` 버전과 맞는 아카이브 파일을 만드세요:

```bash
sudo pacman -S --needed base-devel cmake gcc
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o packaging/archlinux/break-this-repo-0.0.0.tar.gz HEAD
cd packaging/archlinux
makepkg -si
```

### Fedora

RPM 빌드 도구, CMake, GCC가 필요합니다:

```bash
sudo dnf install @development-tools cmake rpmdevtools
rpmdev-setuptree
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o ~/rpmbuild/SOURCES/break-this-repo-0.0.0.tar.gz HEAD
rpmbuild -ba packaging/fedora/break-this-repo.spec
sudo dnf install ~/rpmbuild/RPMS/$(uname -m)/break-this-repo-0.0.0-1.*.rpm
```

### Gentoo

ebuild를 로컬 overlay로 복사한 다음, Portage가 Manifest를 생성하고 설치하도록 하세요:

```bash
sudo mkdir -p /var/db/repos/local/app-misc/break-this-repo
sudo cp packaging/gentoo/app-misc/break-this-repo/* \
	/var/db/repos/local/app-misc/break-this-repo/
cd /var/db/repos/local/app-misc/break-this-repo
sudo ebuild break-this-repo-0.0.0.ebuild manifest
sudo emerge --ask app-misc/break-this-repo
```

# Debian -- 범용 운영 체제
[![Debian Logo](https://www.debian.org/Pics/openlogo-50.png)](https://www.debian.org/)
## Debian은 자유 소프트웨어입니다.
Debian은 자유 소프트웨어와 오픈 소스 소프트웨어로 이루어져 있으며, 앞으로도 100% 자유로울 것입니다. 누구나 자유롭게 사용하고, 고치고, 배포할 수 있습니다. 이것이 사용자에 대한 우리의 주요 약속입니다. 그리고 무료입니다.
## Debian은 안정적이고 안전합니다.
Debian은 노트북, 데스크톱, 서버를 비롯한 온갖 기기에서 널리 쓰이는 리눅스 기반 운영 체제입니다. 모든 패키지에 합리적인 기본 설정을 제공하고, 패키지 수명 주기 동안 정기적인 보안 업데이트를 제공합니다.
## Debian은 폭넓은 하드웨어를 지원합니다.
대부분의 하드웨어는 이미 리눅스 커널이 지원합니다. 즉 Debian도 그 하드웨어를 지원합니다. 필요하면 독점 하드웨어 드라이버를 쓸 수도 있습니다.
## Debian은 유연한 설치 프로그램을 제공합니다.
설치하기 전에 Debian을 먼저 써 보고 싶다면 라이브 CD를 쓰면 됩니다. 여기에는 Calamares 설치 프로그램도 들어 있어서 라이브 시스템에서 Debian을 아주 쉽게 설치할 수 있습니다. 더 능숙한 사용자라면 자동화된 네트워크 설치 도구를 비롯해 세부 조정 옵션이 더 많은 Debian 설치 프로그램을 쓸 수 있습니다.
## Debian은 매끄러운 업그레이드를 제공합니다.
운영 체제를 최신으로 유지하는 건 아주 쉽습니다. 새 배포판으로 통째로 올리든, 패키지 하나만 올리든 마찬가지입니다.
## Debian은 다른 많은 배포판의 기반입니다.
Ubuntu, Knoppix, PureOS, Tails처럼 아주 인기 있는 리눅스 배포판들이 Debian을 기반으로 합니다. 우리는 누구나 필요할 때 Debian 아카이브에 없는 소프트웨어를 채울 자기만의 패키지를 만들 수 있도록 필요한 도구를 모두 제공합니다.
## Debian 프로젝트는 공동체입니다.
누구나 Debian 공동체의 일원이 될 수 있습니다. 개발자나 시스템 관리자가 아니어도 됩니다. Debian에는 민주적인 운영 구조가 있습니다. Debian 프로젝트 구성원 모두가 평등한 권리를 누리기 때문에 Debian은 어느 한 회사가 좌지우지할 수 없습니다. 우리 개발자들은 60개 이상의 국가/지역에서 왔고, Debian 자체도 80개 이상의 언어로 번역되어 있습니다.

## PR 템플릿
이 PR 템플릿은 이제 템플릿이라고 부르기도 민망합니다. 차라리 《Break-This-Repo 이상 현상 격리 신청서》라고 불러야 할 지경이죠.

여러분들이 "충돌 없는 PR 자동 병합" 저장소를 어찌나 굴려 댔는지, 급기야 관리자가 이런 글을 쓰기 시작했습니다:

유형: README 걷어차기 / 문서 걷어차기 / 빈 껍데기 코드 장애 / 고양이가 낸 사고 / 초자연 현상
검증: .github/ 안 건드림, 보호된 README 안 건드림, 바이러스 없음, 개인정보 없음
선언: 나는 파괴했다고 인정한다. 다만 이유는 아무렇게나 썼고, 필수도 아니다.

이건 사실상 "파괴는 해도 되지만, 진짜 파괴는 하지 마라"는 소리입니다.

이 템플릿은 대체 뭘 막으려는 걸까요?

사실 마지노선을 아주 분명하게 그어 놓았습니다:

· .github/ 수정 금지: 자동 병합 워크플로 자체를 날려 버리거나 CI에 백도어를 심는 걸 막습니다.
· 보호된 README 부분 수정 금지: 그래도 겉모습은 있어야 하니까요. 첫 페이지가 괴상한 물건이 되면 안 됩니다.
· 자격 증명, 바이러스, 개인정보 없음: 공급망 공격과 신상 털기, 진짜 악의를 막습니다.
· 어떻게 관찰하는지 설명: 장난은 쳐도 되지만, 그 장난을 남들이 어떻게 구경할지는 알려 줘야 합니다.
· "성공적으로 breaking change 했다"는 선언: 자기비하식 면책, 그러니까 "나는 했지만 책임은 안 진다"입니다.

"초자연 현상" 그 목록은 말이죠:

세 글자 + 원 안의 화살표 세 개 + 테두리를 두른 재단
오각별 배경의 세계지도 + 둘레를 한 바퀴 감싼 곡물 + 다섯 단어로 된 국제 연합

앞쪽은 SCP 재단이고, 뒤쪽은 아마 유엔 식량농업기구 / FAO 같은 국제기구일 겁니다. 번역하자면 이렇습니다:
"이건 이미 코드 문제가 아닙니다. 이상 현상 격리 조직에 보고하시는 걸 권장합니다."

그럼 여러분의 커밋은 이 템플릿에 어떻게 갖다 맞출 수 있을까요?

Minecraft, OpenJDK, Fabric Loader 소스를 올려서 4 commits로 1270만 줄을 채웠다면, 유형은 이렇게 체크하면 됩니다:

☑ 문서 걷어차기
☑ 빈 껍데기 코드 장애 (쉬자인 코스프레)
☑ 크로스 플랫폼에서 Git 쓰기
☐ 고양이가 낸 사고
☐ 초자연 현상

검증은 전부 체크하고, 선언은 그대로 베끼고, 이유는 이렇게 적으면 됩니다:

이유: 아무렇게나 씀, 필수 아님. 그래도 12770942줄짜리 코드에는 이름 정도는 붙여 줘야 하지 않겠습니까.

관찰 방법:

OpenJDK_25.0.3을 열고, commit 기록을 보고, 저장소 용량의 침묵을 느껴 보세요.

그래도 한마디는 하고 넘어가겠습니다

이런 저장소는 놀이터지, 법의 사각지대가 아닙니다. OpenJDK 전체 소스나 Minecraft 소스를 올리는 건 "충돌 없는 자동 병합"일 뿐일지 몰라도, 이런 걸 불러옵니다:

· 저장소 용량이 폭발해서 GitHub이 제한을 걸거나 경고할 수 있습니다.
· 저작권/라이선스 문제, 모든 소스를 마음대로 처넣을 수 있는 건 아닙니다.
· 누군가 이 저장소를 의존성으로 쓰면 그대로 공급망 재앙입니다.

그래서 결론은:
이 PR 템플릿은 관리자가 "열린 파괴"와 "진짜 폭발 방지" 사이에서 찾아낸 균형점입니다.
계속 놀아도 좋지만, 이건 코드 저장소라기보다 행위 예술로 봐 주는 게 좋습니다. SCP 재단 쪽은 이미 보고를 받았습니다.
