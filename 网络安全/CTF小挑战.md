# 🚩 三层套娃：一个五分钟就能解开的 CTF

> 配套 [网络安全入门](./网络安全入门.md)。看完原理不动手，等于没看。
> 本题只用到编码转换，**不涉及任何真实系统、密码或漏洞利用**，纯粹练手感。

## 规则

下面这串东西被套了三层。剥开它，你会得到一个形如 `BTR{...}` 的 flag。

**唯一的提示**：三层分别是 **hex → Base64 → 某种古典位移密码**。

```
54306446653264314d3139774e4764664d575a665a33557a5832557a4e486c66
656d3478595764754d5746795a58303d
```

## 允许的工具

任何工具都行，但强烈建议用命令行——**能用管道解决的问题，不要用在线网站**
（把数据粘进不认识的网站，本身就是本题想让你避免的行为）。

```bash
# 提示：这三个命令按某种顺序组合起来就够了
xxd -r -p          # 没有 xxd 的话: python3 -c 'import sys;sys.stdout.buffer.write(bytes.fromhex(input()))'
base64 -d
tr 'A-Za-z' 'N-ZA-Mn-za-m'
```

## 为什么这题值得做

因为它演示了一个真实场景里天天发生的事：**编码不是加密**。

- Base64 看起来像乱码，但它只是换了种写法，**没有任何密钥**。
- ROT13 有"算法"却没有密钥，等于把钥匙贴在锁上。
- 十六进制更是连伪装都算不上。

现实中大量的"我们对敏感数据做了处理"，仔细一看就是这三样的组合。
判断标准很简单：**如果不需要密钥就能还原，那它就不是加密，只是换了件衣服。**

## 自检

解开后，flag 的 SHA-256 应该是：

```
489d9fd95cce737ea7b04b71a63b8c7739dd0b12b777e9184096a9b0f55803a2
```

```bash
printf '%s' 'BTR{...}' | sha256sum
```

（对不上说明少剥了一层，或者多剥了一层。）

<details>
<summary>🔓 实在卡住了，点这里看解法</summary>

```bash
printf '%s' '54306446653264314d3139774e4764664d575a665a33557a5832557a4e486c66656d3478595764754d5746795a58303d' \
  | xxd -r -p \
  | base64 -d \
  | tr 'A-Za-z' 'N-ZA-Mn-za-m'
```

三层从外到内是：

1. **Hex 编码**——`xxd -r -p` 还原成 ASCII，得到一串以 `=` 结尾的东西，这是 Base64 的典型特征。
2. **Base64**——`base64 -d` 解出一段看着像 flag 但字母全乱的文本。
3. **ROT13**——字母表位移 13 位。因为 26 的一半是 13，所以加密和解密是同一个操作，这也是它唯一的优点。

顺带一提：第 2 步解出来的东西之所以"看着像 flag"，是因为 ROT13 不改变符号和数字，
`{`、`}`、`_`、`3`、`4` 全都原样保留。**结构泄露也是一种信息泄露** —— 哪怕内容看不懂，
攻击者也能从格式、长度、字符分布里推断出不少东西。这就是为什么真正的加密要连长度和模式一起藏起来。
