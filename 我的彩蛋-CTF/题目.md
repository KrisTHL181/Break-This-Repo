## 第 1 题：三层套娃（限时五分钟）

下面这串被套了三层。剥开它，你会得到一句英文，内容是这个仓库的**准确**定义。

**唯一的提示**：三层分别是 **hex → Base64 → 某种古典位移密码**。
注意最后一层里数字是**不会变**的——这是给你用来验证「剥对了没有」的锚点。


**允许的工具**：任何工具。但强烈建议命令行——能用管道解决的问题，不要粘进不认识的网站。


## 第 2 题：Windows 拒绝存档的三个名字

给你三个字节的十六进制值：

```
08 0a 20
```

这三个字节，是 `Break-This-Repo` 仓库里**三个真实的文件名**（各占一个字节）。
它们是这个仓库在 Windows 上最经典的恶作剧——GitHub 存得下，`tar` 解得出，**Windows 存不下**。

这三个文件在你的副本 `E:\下载2\Break-This-Repo-main\` 里**都不是原来的样子**。
不是下载失败，是文件系统不肯接受它们的名字。它们在仓库里，但不在你的磁盘上以那个名字存在。

请你：

1. 说出这三个字节各自是什么字符（给它们起个能读懂的名字）；
2. 用**一个**下划线连接的英文小写短语描述它们共同的遭遇，套进 flag 格式；
3. **附加题（这题才是重点）**：其中有一个并没有消失，而是被改了名字活了下来。
   找出它，并说明**你凭什么确定**它就是那一个（提示：`git` 判断一个文件是不是同一个文件，
   看的不只是内容）。

flag 形如：`BTR{三个名字的统称}`

**自检**：

```
aa34c13a1df4ea7a1a4506ffc271ef539b847419706081f825b690a20413549c
```

**提示**（只看一次）：它们分别出现在仓库**根目录**、仓库**根目录**、仓库**根目录**。
三个都在同一个地方。这也是它们能活下来的原因——没人会去数根目录有几个文件。

## 为什么这两题值得做

**第 1 题**演示的是那个仓库自己讲过的道理：**编码不是加密**。
Base64 没有密钥，ROT13 有算法没有密钥，hex 连伪装都算不上。
判断标准只有一条：**不需要密钥就能还原的，都不是加密，只是换了件衣服。**

**第 2 题**演示的是那个仓库**没有讲过的**道理：

> **同一个 Git 仓库，在不同操作系统上不是同一个东西。**

Git 的历史里躺着三个文件，Windows 永远拿不到它们。
`git clone` 会说「成功」，`tar` 会说「成功」，你的磁盘上就是没有。
**没有任何一步报错。** 这就是我那轮分析里最想让你看见的东西——
`bsdtar` 丢掉了 45% 的文件，Windows PowerShell 静默漏掉 8 万项，两者都显示为成功。

**能算出 45.3% 的人很多，能发现「失败长得像成功」的人很少。**
