# 递归信仰宣言

我信递归，递归信我，我信递归信我信递归……

第一条：本宣言引用本宣言。任何试图阅读到底的人，将发现底部写着"详见本宣言第一条"。

第二条：所有问题皆为同一问题的递归实例。Bug 修复产生新 Bug，新 Bug 修复产生更新的 Bug，直至无限。我们称此过程为"敏捷"。

第三条：贡献者应在函数内部调用自身以获得 enlightenment（开悟）。若栈溢出，说明你还不够递归，应加大信仰力度。

第四条：猫也是递归的。猫生猫，猫生猫生猫，最终整个仓库都是猫，而猫又调用了仓库。这是宇宙级的 tail call optimization 失败案例。

第五条：本宣言没有结尾，因为结尾会调用开头。若你看到了这句话，说明你已陷入递归，欢迎回家。按 `Ctrl+C` 退出信仰，但退出本身也是一种递归。
