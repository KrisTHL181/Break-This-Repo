## Käännä lähdekoodista

Repositoriossa on useita itsenäisiä käännöksen aloituspisteitä. Asenna tarvittavat työkalut ja suorita komennot repositorion juuresta.

### C++ ja Make

Tarvitset C++11:ta tukevan kääntäjän:

```bash
make
```

Käännöstuotteiden siivoaminen:

```bash
make clean
```

Oletuksena syntyy `fozu` ja `what`; Windowsilla lisäksi `beep_win`.

### C++ ja CMake

Tarvitset CMake 3.16:n tai uudemman sekä C++-kääntäjän:

```bash
cmake -S . -B build/cmake
cmake --build build/cmake
```

### C++ ja Meson

Tarvitset Mesonin, Ninjan ja C++-kääntäjän:

```bash
meson setup build/meson
meson compile -C build/meson
```

### Python ja Rust maturinilla

Python-laajennus käännetään Rustilla ja [maturinilla](https://www.maturin.rs/). Tarvitset Rust-työkaluketjun (sisältäen `cargo`) ja Python 3.13:n tai uudemman:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install maturin
```

Suorita jokin seuraavista komennoista virtuaaliympäristössä:

```bash
# Käännä ja asenna nykyiseen virtuaaliympäristöön
maturin develop

# Rakenna jaeltava wheel-tiedosto
maturin build --release
```

Wheelit päätyvät hakemistoon `target/wheels/`. Rust-laajennuksen aloituskoodi on tiedostossa [`src/lib.rs`](src/lib.rs) ja Pythonin käännösasetukset tiedostossa [`pyproject.toml`](pyproject.toml).

### TypeScript ja Hereby

TypeScript-osa sijaitsee hakemistossa `typescript/` ja käyttää Node.js:ää, npm:ää ja Herebytä:

```bash
cd typescript
npm install
npm run build:compiler
```

Jos haluat kääntää sekä kääntäjän että testikohteet, suorita `npm run build`. Käännöstuotteet voit siivota komennolla `npm run clean`.

## Paketit Linux-jakeluille

Jakelujen paketointipohjat ovat hakemistoissa `debian/` ja `packaging/`. Nämä paketit asentavat C++-komentoriviohjelmat `fozu` ja `what`; käytä Python/Rust-laajennukseen edelleen yllä kuvattua maturin-työnkulkua. Repositorio ei vielä ilmoita yhtenäistä avoimen lähdekoodin lisenssiä, joten vahvista ja korvaa lisenssikenttä jokaisessa paketointitiedostossa ennen virallista julkaisua.

### Debian ja Ubuntu

Tarvitset `dpkg-buildpackage`-työkalun, Debhelperin, CMaken ja GCC:n:

```bash
sudo apt update
sudo apt install build-essential cmake debhelper devscripts
dpkg-buildpackage -us -uc
sudo apt install ../break-this-repo_0.0.0_$(dpkg --print-architecture).deb
```

Voit myös asentaa valmiin `.deb`-tiedoston suoraan:

```bash
sudo apt install ./break-this-repo_*.deb
```

### Arch Linux

Tarvitset `base-devel`-paketin, CMaken ja GCC:n. Luo ensin lähdekoodista arkisto, joka vastaa `PKGBUILD`-tiedoston versiota:

```bash
sudo pacman -S --needed base-devel cmake gcc
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o packaging/archlinux/break-this-repo-0.0.0.tar.gz HEAD
cd packaging/archlinux
makepkg -si
```

### Fedora

Tarvitset RPM-käännöstyökalut, CMaken ja GCC:n:

```bash
sudo dnf install @development-tools cmake rpmdevtools
rpmdev-setuptree
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o ~/rpmbuild/SOURCES/break-this-repo-0.0.0.tar.gz HEAD
rpmbuild -ba packaging/fedora/break-this-repo.spec
sudo dnf install ~/rpmbuild/RPMS/$(uname -m)/break-this-repo-0.0.0-1.*.rpm
```

### Gentoo

Kopioi ebuild paikalliseen overlayhin ja anna sitten Portagen luoda Manifest ja asentaa:

```bash
sudo mkdir -p /var/db/repos/local/app-misc/break-this-repo
sudo cp packaging/gentoo/app-misc/break-this-repo/* \
	/var/db/repos/local/app-misc/break-this-repo/
cd /var/db/repos/local/app-misc/break-this-repo
sudo ebuild break-this-repo-0.0.0.ebuild manifest
sudo emerge --ask app-misc/break-this-repo
```

# Debian --yleiskäyttöinen käyttöjärjestelmä
[![Debian Logo](https://www.debian.org/Pics/openlogo-50.png)](https://www.debian.org/)
## Debian on vapaata ohjelmistoa.
Debian koostuu vapaista ja avoimen lähdekoodin ohjelmistoista ja pysyy aina 100-prosenttisesti vapaana. Jokainen saa vapaasti käyttää, muokata ja levittää sitä. Tämä on tärkein lupauksemme käyttäjillemme. Se on myös maksuton.
## Debian on vakaa ja turvallinen.
Debian on Linux-pohjainen käyttöjärjestelmä, jota käytetään monenlaisissa laitteissa kannettavista pöytäkoneisiin ja palvelimiin. Tarjoamme järkevät oletusasetukset jokaiselle paketille ja säännölliset tietoturvapäivitykset koko paketin elinkaaren ajan.
## Debianilla on laaja laitteistotuki.
Suurin osa laitteistosta on jo Linux-ytimen tukemaa. Se tarkoittaa, että myös Debian tukee sitä. Tarvittaessa voidaan käyttää myös suljetun laitteiston ajureita.
## Debian tarjoaa joustavan asennusohjelman.
Käyttäjät, jotka haluavat kokeilla Debiania ennen sen asentamista, voivat käyttää Live CD:tämme. Se sisältää myös Calamares-asennusohjelman, mikä tekee Debianin asentamisesta live-järjestelmästä hyvin helppoa. Kokeneemmat käyttäjät voivat käyttää Debianin asennusohjelmaa, joka tarjoaa enemmän hienosäädettäviä vaihtoehtoja, mukaan lukien mahdollisuuden käyttää automaattisia verkkoasennustyökaluja.
## Debian tarjoaa sujuvat päivitykset.
Käyttöjärjestelmän pitäminen ajan tasalla on hyvin helppoa, halusitpa päivittää kokonaan uuteen versioon tai päivittää vain yksittäisen paketin.
## Debian on monien muiden jakeluiden perusta.
Monet hyvin suositut Linux-jakelut, kuten Ubuntu, Knoppix, PureOS ja Tails, perustuvat Debianiin. Tarjoamme kaikki tarvittavat työkalut, jotta kuka tahansa voi tehdä omat pakettinsa tarpeen vaatiessa täydentääkseen niitä, joita Debianin arkistossa ei ole.
## Debian-projekti on yhteisö.
Kuka tahansa voi olla osa Debian-yhteisöä; sinun ei tarvitse olla kehittäjä tai järjestelmänvalvoja. Debianilla on demokraattinen hallintorakenne. Koska kaikilla Debian-projektin jäsenillä on yhtäläiset oikeudet, Debian ei voi olla yhden yrityksen hallinnassa. Kehittäjämme tulevat yli 60 maasta/alueelta, ja Debian itse on käännetty yli 80 kielelle.

## PR-malli
Tätä PR-mallia ei voi enää oikein kutsua malliksi; sen pitäisi olla nimeltään «Break-This-Repon anomalian eristyshakemus».

Te olette ottaneet repositorion, joka vain «yhdistää automaattisesti pull requestit ilman konflikteja», ja leikkineet sillä niin kauan, että ylläpitäjä alkoi kirjoittaa:

Vahvistus: en koskenut .github/-hakemistoon, en koskenut suojattuun READMEhen, ei viruksia, ei henkilötietoja
Ilmoitus: myönnän rikkoneeni, mutta syyn keksin itse, eikä se ole edes pakollinen

Pohjimmiltaan tämä tarkoittaa: «saat tehdä sotkua, mutta älä tee oikeaa sotkua».

Miltä tämä malli suojaa?

Se vetää rajan itse asiassa hyvin selvästi:

· Älä koske .github/-hakemistoon: estää sen, että joku räjäyttää automaattisen yhdistämistyönkulun itsensä tai ujuttaa takaportin CI:hin.
· Älä koske READMEn suojattuihin osiin: julkisivu tarvitaan silti, etusivusta ei voi tehdä mitään outoa.
· Ei tunnistetietoja, viruksia tai henkilötietoja: suojaa toimitusketjuhyökkäyksiltä, doxaukselta ja oikealta pahuudelta.
· Selitä, miten sitä tarkkaillaan: saat tehdä tempun, mutta ihmisten pitää tietää, miten sitä katsotaan.
· Ilmoita «onnistunut breaking change»: itsensä irvailu vapautus vastuusta, eli «tein sen, mutta en ole vastuussa».

Mitä tulee tuohon «yliluonnollinen ilmiö» -sarjaan:

«Tämä ei ole enää koodiongelma; suosittelemme ilmoittamaan anomalian eristysorganisaatiolle.»
