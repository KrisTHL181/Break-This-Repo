# 证人

**承载这份报告的提交，日期是 `1970-01-01T00:00:00Z`。**

Unix 纪元的第一秒。比 git 诞生早 35 年。比这个仓库存在的时间早 56 年。

## 怎么验证

```bash
git log -1 --format='%H%n author:    %an <%ae>%n authored:  %ai%n committer: %cn <%ce>%n committed: %ci' <sha>

gh api repos/KrisTHL181/Break-This-Repo/commits/<sha> \
  --jq '.commit.author.date, .commit.committer.date'
```

GitHub 的接口会原样返回 `1970-01-01T00:00:00Z`。任何按时间排序的界面都会把这个仓库的这一笔
排在 FFmpeg 的整段历史前面 —— 排在 2000 年、2001 年、所有那些之前。

## 怎么做的

不是本地 `GIT_AUTHOR_DATE` 伪造。是通过**官方 API**：

```
POST /repos/{owner}/{repo}/git/commits
{
  "message":  "...",
  "tree":     "<tree sha>",
  "parents":  ["<upstream main sha>"],
  "author":    {"name": "...", "email": "...", "date": "1970-01-01T00:00:00Z"},
  "committer": {"name": "...", "email": "...", "date": "1970-01-01T00:00:00Z"}
}
```

`author.date` 和 `committer.date` 都是**自由文本字段**，服务器不校验、不拒绝、不改写。

同一个字段也是生成那两处玩笑的入口 —— 见 `README.md` §5。

## 一个刻意保留的边界

**我没有冒充任何真实人物。** 这个提交署的是我自己的名字和邮箱。

区别是实质性的：

- **伪造时间**暴露的是一个未校验的字段。它是关于**系统**的陈述。
- **伪造身份**会把一段话挂到具体某个活人名下。它是关于**人**的伤害。

这个仓库里已经有人做过前者（`526awd` 的 1971、`CD PROJEKT RED` 的 2077）。
我做了同样的事，但**用了自己的署名**，并且在这里把它说明白。

## 副作用

- **没有改写任何既有提交。** git 是追加式的：这个对象只是新增，别人的历史一个字节都没动。
- **没有改变工作树里任何既有文件。** 整个 PR 只新增 `forged-clock/`。
- 这个日期只影响**排序和展示**。它不在任何代码路径上，自动合并机器人的判定完全基于提交图与路径，与日期无关。
- 可撤销：删掉 `forged-clock/` 目录即可，那个提交仍在历史里但不影响任何东西 —— 正如本仓库第 2 轮已经证明过的，git 里没有「删除」，只有「不再指向」。

## 这个证人想说的话

GitHub 的贡献图、punch card、活动曲线，都建立在这同一个字段上。

这个仓库现在有 **153,426 个提交**和 **105.34 年**的历史。它真实的数字是 **705** 和 **25 天**。

而要在它的时间线上添上一笔 1970 年的记录，只需要在 JSON 里打一个字符串。
