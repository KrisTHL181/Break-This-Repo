# COMPLIANCE — 合规改造记录

本文件说明：为了让这套知识库**可以公开分发**，相对于原始素材做了哪些改造、
为什么这么做，以及**残留风险**和你想补齐内容时的正确做法。

---

## 1. 一句话结论

原始素材里混着三类东西：**CC 许可的社区文本**、**整合包自带文本（CC BY-NC-SA 4.0）**、
以及**根本不适用 CC 许可的游戏版权素材**。第三类是本包唯一的高风险项，
因此改造的核心动作就是：**只留文字，剔除一切游戏版权素材。**

---

## 2. 改造清单

### 2.1 已剔除：Minecraft / 模组贴图与其它二进制素材

- **剔除了什么**：约 6700 个图片文件（约 164 MB），以及所有 jar、音效、字体、模型文件。
- **为什么不放**：Minecraft 原版贴图、模型、音效是 Mojang / Microsoft 的版权素材，
  **不在任何 CC 许可覆盖范围内**，公开仓库分发属于侵权风险；各模组的资产同理，
  多数模组为 All Rights Reserved 或自有许可。
- **本包的做法**：不附带图片。站点访问 `/assets/<file>` 时返回 1×1 透明占位 PNG，
  页面其余部分（正文、检索、任务书）正常工作。
- **终端用户如何补齐**（合法路径）：用户用**自己合法拥有的游戏安装**导出图片，
  放进 `assets/` 目录，或用环境变量指定：
  ```bash
  set GTNH_KB_ASSETS=D:\my-gtnh-assets
  python kbweb/serve.py
  ```
  即"素材在用户本机生成，不随包传播"。

### 2.2 已剔除：第三方任务书汉化叠加层

- **剔除了什么**：把任务书任务名/描述中文化的第三方汉化对照表。
- **为什么**：它是对整合包文本的**翻译衍生作品**，版权与署名归属第三方汉化项目，
  需要单独取得署名与分发依据，不属于本汇编可自行决定的许可范围。
- **影响**：任务书只显示**英文原文**（整合包原始文本，CC BY-NC-SA 4.0，署名清晰）。
- **想启用**：把汉化表放到 `i18n/bq_quest_zh.tsv`（列：任务ID / 中文名 / 中文描述），
  重跑 `kbweb/build_site.py`。请自行确认该汉化项目的许可与署名要求。

### 2.3 已剔除：生成物与缓存

- `kb/data/index.pkl`（约 145 MB）、`kbweb/data/**`（约 177 MB）都是**可从本包数据重建**的
  派生物，不必入库，也不该入库（会撑大仓库、产生无意义的巨大 diff）。
- 已写入 `.gitignore`；重建命令见 `README.md`。

### 2.4 已保留：文字语料与工具

| 保留内容 | 依据 |
|---|---|
| 维基正文抽取（`kb/wiki/*.jsonl`） | CC BY-NC-SA 3.0 / 部分 CC BY-SA 3.0，署名见 `NOTICE.md` |
| 任务书英文全文（`kb/quests/*.txt`） | 整合包 CC BY-NC-SA 4.0 |
| config 参考值（`kb/ref/*`） | 整合包 CC BY-NC-SA 4.0 |
| 物品名对照表 | 短名称字符串，非独创表达；随整合包 CC BY-NC-SA 4.0 |
| 索引与检索工具 | 本项目自有代码，CC BY-NC-SA 4.0 |

**没有做**"把原始素材换个皮就算合规"这类表面动作：改名不改变版权归属，
唯一的合规路径是**移除不受许可覆盖的部分**。

## 3. 残留风险（公开发布前请自行判断）

1. **NC 条款 + 公开仓库**
   三个数据源都是**禁止商业使用**许可。若承载仓库本身通过广告、赞助、
   付费会员等方式变现，可能被主张构成商业性使用。建议：置于无变现的公开仓库，
   或仅在私有/内部环境部署。

2. **ShareAlike 的传染性**
   衍生作品必须以 CC BY-NC-SA 4.0 分发。若把本包并入一个采用其它许可（如 MIT、
   Apache-2.0）的仓库，**该仓库对本包的再分发仍受 NC+SA 约束**，
   不能通过换仓库许可来"洗掉"它。

3. **"自动合并 PR" 的仓库会稀释合规性**
   如果承载仓库会自动合并任意 PR，任何人都能修改甚至删掉 `NOTICE.md` / `LICENSE`。
   一旦署名或许可文件被他人改动、删除，你的分发就可能不再合规。
   → 建议放在**你自己可控**的仓库；若必须放在会自动合并的仓库，
   请在仓库根 `README` 中另行固定署名与许可，或定期核对。

4. **逐页署名的精度**
   本包对维基正文采用**聚合署名**（整个维基的贡献者集合）。
   CC BY 的要求是"合理方式署名"；更严谨的做法是逐页链接到
   `https://wiki.gtnh.industries/` 的对应页面与历史版本。
   如果权利人提出更高要求，应改为逐页署名。

5. **不构成法律意见**
   以上是基于公开许可文本与站点声明的**工程性判断**，不是法律意见。
   用于商业场景前请咨询律师。

## 4. 复现这份合规改造

```bash
# 1) 取文字语料（维基正文 / 任务书 / config）
python tools/extract_wiki.py --help

# 2) 剔除所有非文本文件
#    本包内不应存在 .png .jpg .gif .jar .ogg .ttf 等；自检：
python - <<'PY'
import os
BAD = ('.png','.jpg','.jpeg','.gif','.webp','.jar','.ogg','.ttf','.zip','.mp3','.mp4')
hit = [os.path.join(r,f) for r,_,fs in os.walk('.') for f in fs if f.lower().endswith(BAD)]
print('二进制素材:', hit or '无')
PY

# 3) 重建索引与站点
python kb/search.py --rebuild
python kbweb/build_site.py && python kbweb/site_pack.py
```
