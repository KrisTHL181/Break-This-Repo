## 第 1 题答案

### 完整解法

```bash
printf '%s' '54325679626e6774523356325a693146636d4e694f6941784e4467354e54516763335a35636d59734944597a4e54516763585a6c636e426e596d5632636d5973494449754d5451334946525049433067626d4678494451314c6a4d6759334a6c63484a685a7942696379426e64574a6d6369427a646e6c795a6942755a58496762584a6c59694276624764795a69343d' \
  | xxd -r -p \
  | base64 -d \
  | tr 'A-Za-z' 'N-ZA-Mn-za-m'
```

三层从外到内：

1. **Hex** —— `xxd -r -p` 还原出一串以 `=` 结尾的 ASCII，这是 Base64 的典型特征。
2. **Base64** —— `base64 -d` 解出一段字母全乱但**数字和符号完好**的文本。
3. **ROT13** —— 字母表位移 13 位。26 的一半是 13，所以加密与解密是同一个操作。

### 明文

```
Break-This-Repo: 148954 files, 6354 directories, 2.147 GB - and 45.3 percent of those files are zero bytes.
```

### 为什么我选了这句话

因为这句里的三个数字，**是同一件事的三个视角**：

| 数字 | 含义 | 谁在乎它 |
|---|---|---|
| 2.147 GB | 仓库体积 | GitHub（用于显示"大小"） |
| 148954 | 文件数 | 几乎没人看 |
| **45.3%** | **零字节文件占比** | **只有数过一遍的人知道** |

GitHub 用体积给仓库排名。于是 67,369 个由 `许家印/1.py` 灌进去的空文件，
在仓库首页上**完全隐形**——它们加起来只占 24.3 MB，1.1%。
**度量口径决定了什么算"大"。** 这是这道题真正想让你带走的东西。

### 校验

```bash
printf '%s' 'Break-This-Repo: 148954 files, 6354 directories, 2.147 GB - and 45.3 percent of those files are zero bytes.' | sha256sum
# e8aea6b909c79b048eb2779e9a02d73084e93c979ccc7027f1a75958615404b4
```

> ⚠️ 注意：本仓库里那道原生 CTF 的答案，用某些 `sha256sum` 会算不出来——
> 因为 `printf '%s'` 不带 BOM，而 PowerShell 的 `[Text.Encoding]::UTF8` **带** BOM。
> 我第一次验证时就被这个坑了一下（详见 `E:\APP\deepseek\_btr\` 里的分析记录）。
> **同一个"UTF-8"，在两个工具里可以不是同一个东西。**

## 第 2 题答案

| 字节 | 字符 | 在 Windows 上为什么不行 |
|---|---|---|
| `08` | `\b` 退格符 (Backspace) | 属于 C0 控制字符，Win32 文件 API 直接拒绝 |
| `0a` | `\n` 换行符 (Line Feed) | 同上；且任何按行读的脚本都会把它当成行尾 |
| `20` | `" "` 单个空格 | 语法上合法，但结尾空格会被 `CreateFile`/资源管理器静默剥离，导致「创建了但找不到」 |

### flag

```
BTR{names_that_windows_refused}
```

```bash
printf '%s' 'BTR{names_that_windows_refused}' | sha256sum
# aa34c13a1df4ea7a1a4506ffc271ef539b847419706081f825b690a20413549c
```

### 它们在哪儿

三个都在**仓库根目录**（`Break-This-Repo-main\`）。但它们的下场**并不相同**——
这是本题真正难的地方，也是出题人（我）一开始判断错的地方：

| 仓库中的名字 | 大小 | 内容 | 你磁盘上的结果 |
|---|---|---|---|
| `\b` (U+0008) | 0 B | （空） | ❌ **完全消失** |
| `\n` (U+000A) | 7 B | `你好\n` | ❌ **完全消失** |
| `" "` (U+0020) | 7 B | `滚木\n` | ⚠️ **改名成 `_` 活了下来** |

**所以你目录里那个莫名其妙的 `_` 文件，不是垃圾。**
它是仓库里名为「一个空格」的文件。验证方式（git blob SHA 是唯一身份）：

```powershell
# 计算 "_" 的 git blob hash
$b = [IO.File]::ReadAllBytes('E:\下载2\Break-This-Repo-main\_')
$header = [Text.Encoding]::ASCII.GetBytes("blob $($b.Length)`0")
$full = New-Object byte[] ($header.Length + $b.Length)
[Array]::Copy($header,0,$full,0,$header.Length)
[Array]::Copy($b,0,$full,$header.Length,$b.Length)
(([BitConverter]::ToString((New-Object Security.Cryptography.SHA1Managed).ComputeHash($full))).Replace('-','')).ToLower()
# => d35eef3419e44dcc4b063e226b184a0509bbbb40
#    与 GitHub 上名为空格的文件的 blob sha 完全一致
```

而两个真正的失踪者（`\b` 是 0 字节，`\n` 是 7 字节的 `你好\n`），
**连一个改名后的替身都没留下**——因为 Win32 文件 API 在 `CreateFile` 阶段就拒绝了它们，
bsdtar 只在 67,780 行输出里留下一行 `Invalid argument`，退出码 1。

**三个文件加起来 14 字节。它们让这份副本在 Windows 上不再是仓库本身。**

### 完整差异清单

见 `E:\1\仓库差异-缺失的3个文件名.txt`（含三个文件的 blob sha、HTTP 直链、复现命令）。

### 这道题真正的答案

不是那三个字符。是这个事实：

> **`git clone` 显示成功，`tar -x` 显示成功，磁盘上就是少了三个文件，没有任何一步报错。**

我在那轮分析里撞见的是同一件事的放大版：
- `bsdtar` 解压 codeload tarball 时**丢了 45% 的文件**，退出码只有一行 `Invalid empty pathname`，夹在 67,780 行输出里；
- Windows PowerShell 5.1 的 `Get-ChildItem -Recurse` 遇到非法文件名会**静默放弃整个子树**，8 万项消失，零报错；
- 换成 `-LiteralPath` + .NET `[IO.Directory]::GetFiles()` 才数对：148,954。

**「失败长得像成功」，是我读完这个仓库后唯一想让人记住的一句话。**

## 加练参考答案（简）

**1. `tr` 为什么加解密同写法？**
因为 ROT13 是**对合运算**（involution）：位移 13 位再位移 13 位 = 位移 26 位 ≡ 0。
它成立的前提是字母表长度 26 是偶数，且位移量恰好是它的一半。
换成"ROT5 作用在字母上"就不成立了——这也是我出题时踩的坑：
我第一版写了「字母 ROT13 + 数字 ROT5」并且声称自反，**验证脚本当场把它推翻了**（反解出 `Lboku-Drsc-Bozy`）。
我把它改成了「字母 ROT13 + 数字不动」，并特意把数字放进明文当锚点。
**这个坑本身比题目值钱：`rot(rot(x)) == x` 这种"显然"的东西，不验证就是会错。**

**2. 如果那三个文件有内容会怎样？**
受害的是**任何在 Windows 上克隆这个仓库的人**：
- `\b` 和 `\n` 的文件名会让递归删除/备份工具误判路径（`\b` 在很多 shell 里是转义序列，`\n` 断行）；
- 结尾空格的文件名会让「备份了但恢复不出来」成为可能——文件在，名字回不去；
- 如果是可执行内容，配合文件名混淆可以做到**在你没运行任何东西的情况下让扫描器失明**。
  这就是"文件名也是攻击面"（那个仓库的威胁建模文档讲过同一条，只是换成了 git 引号转义）。

**3. 你手上这份副本 vs GitHub 的 `main`，差异来源至少三种：**
- **文件系统**：Windows 不允许的名字（本题三个），以及 609 字符超长路径在不同工具下的截断/丢失；
- **时间**：`main` 每 30 分钟被 cron 自动合并一次，你解压的是某个 commit 的快照。REST 搜索接口说 400 个 PR，实际编号已到 #425——**连 GitHub 自己的两个接口都对不上**；
- **编码**：同一个 tar 包，`bsdtar` 在 CP936 locale 下解出的中文名是乱码，换 UTF-8 才能读对；
- **第四条（最难察觉）**：`.git` 目录不在 tarball 里。你手上是**工作树**，不是**仓库**。没有历史、没有分支、没有 PR 记录——**不可抵赖性恰好是那个仓库唯一真正的安全保证，而它不在你手上。**
