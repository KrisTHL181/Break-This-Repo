# 网络安全入门：一篇给普通人的短文

> 作者：mochiaochen · 博客：<https://mochiaochen.github.io>

网络安全（Cybersecurity）常被说得神神秘秘，仿佛只属于黑客电影里的绿色瀑布代码。但它的内核其实很朴素：**让该访问的人访问得到，让不该访问的人访问不到，并且在出事时能发现、能恢复。**

## 一、三根支柱：CIA 三元组

几乎所有安全措施，最后都能归到这三个词上：

| 支柱 | 含义 | 被破坏时会发生什么 |
| --- | --- | --- |
| 机密性 Confidentiality | 信息只对被授权者可见 | 数据库泄露、聊天记录被围观 |
| 完整性 Integrity | 信息不被悄悄篡改 | 转账金额被改、下载的安装包被投毒 |
| 可用性 Availability | 需要时服务是在的 | 网站被打瘫、文件被勒索软件锁死 |

加密解决机密性，签名与校验和解决完整性，备份与容灾解决可用性。看到一个新技术时，先问它在保护哪一根柱子，理解会快很多。

## 二、常见威胁速览

- **钓鱼（Phishing）**：伪装成可信来源骗你交出密码或点开附件。它攻击的是人，不是机器，因此也是成本最低、成功率最高的一类攻击。
- **弱口令与撞库**：同一个密码在 A 站泄露，攻击者拿去登录 B 站。人类复用密码的习惯，是攻击者最稳定的收入来源。
- **注入类漏洞**：SQL 注入、命令注入、XSS，本质都是同一个错误——**把用户输入当成了代码来执行**。
- **中间人攻击**：在不可信的网络里明文传输，等于把明信片交给陌生人转交。
- **供应链攻击**：不直接攻击你，而是污染你依赖的第三方库、镜像或更新通道。
- **勒索软件**：加密你的文件再索要赎金。它同时打击可用性和你的心情。

## 三、防御的基本原则

1. **纵深防御**：不要指望单一环节万无一失，多设几道门，让攻击者每一步都要付出代价。
2. **最小权限**：一个账号、一个服务、一个 token，只给它完成工作所需的最小权限。
3. **默认不信任（Zero Trust）**：不因为"来自内网"就放行，每一次访问都要重新验证身份。
4. **纵使被攻破也要能察觉**：日志、监控、告警的价值不在于阻止入侵，而在于缩短"从被入侵到被发现"的时间。
5. **假设会出事**：定期备份，并且真的演练一次恢复流程——没验证过的备份不算备份。

## 四、普通人今天就能做的五件事

1. 用密码管理器，为每个网站生成不同的随机密码。
2. 给邮箱、社交账号、代码托管平台开启二次验证（优先用 TOTP 或硬件密钥，其次才是短信）。
3. 及时打系统与浏览器更新——大多数真实入侵利用的是早已有补丁的老漏洞。
4. 对"紧急""限时""立刻点击"的消息保持怀疑，换一个渠道核实再行动。
5. 重要数据遵循 3-2-1 备份：3 份副本、2 种介质、1 份异地。

## 五、给开发者的补充清单

- 永远不要拼接字符串来构造 SQL，使用参数化查询。
- 对所有外部输入做校验，对所有输出做上下文相关的转义。
- 密码用 bcrypt / scrypt / Argon2 加盐哈希存储，不要自创加密算法。
- 密钥、token 放进环境变量或密钥管理服务，绝不提交进 Git 仓库。
- 锁定依赖版本并定期扫描已知漏洞（`npm audit`、`pip-audit`、Dependabot 等）。
- 全站 HTTPS，并配置 HSTS、CSP 等安全响应头。

## 六、写在最后

安全从来不是一个"做完了"的状态，而是一个持续的过程。它的目标也不是"绝对安全"——这不存在——而是**把攻击成本抬高到超过攻击收益**。

从今天换一个强密码开始，就已经比昨天更安全了。
