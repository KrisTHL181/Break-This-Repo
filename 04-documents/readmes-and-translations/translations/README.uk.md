## Збірка з вихідного коду

Репозиторій містить кілька незалежних точок входу для збірки. Встанови потрібні інструменти й запускай команди з кореня репозиторію.

### C++ з Make

Потрібен компілятор, що підтримує C++11:

```bash
make
```

Щоб очистити артефакти збірки:

```bash
make clean
```

За замовчуванням створюються `fozu` і `what`; у Windows також `beep_win`.

### C++ з CMake

Потрібен CMake 3.16 або новіший і компілятор C++:

```bash
cmake -S . -B build/cmake
cmake --build build/cmake
```

### C++ з Meson

Потрібні Meson, Ninja і компілятор C++:

```bash
meson setup build/meson
meson compile -C build/meson
```

### Python і Rust з maturin

Розширення Python збирається з Rust і [maturin](https://www.maturin.rs/). Потрібен Rust-інструментарій (з `cargo`) і Python 3.13 або новіший:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install maturin
```

У віртуальному середовищі запусти одну з цих команд:

```bash
# Скомпілювати й встановити в поточне віртуальне середовище
maturin develop

# Зібрати wheel-файл для розповсюдження
maturin build --release
```

Wheel-файли створюються в `target/wheels/`. Вхідний код розширення Rust — у [`src/lib.rs`](src/lib.rs), а конфігурація збірки Python — у [`pyproject.toml`](pyproject.toml).

### TypeScript з Hereby

Частина TypeScript міститься в `typescript/` і використовує Node.js, npm і Hereby:

```bash
cd typescript
npm install
npm run build:compiler
```

Якщо хочеш зібрати і компілятор, і тестові цілі, запусти `npm run build`. Щоб очистити артефакти збірки, можна запустити `npm run clean`.

## Пакунки для дистрибутивів Linux

Шаблони пакування для дистрибутивів містяться в `debian/` і `packaging/`. Ці пакунки встановлюють C++ програми командного рядка `fozu` і `what`; для розширення Python/Rust усе ще використовуй описаний вище процес із maturin. Репозиторій поки не декларує єдиної ліцензії відкритого коду, тож перед офіційним випуском перевір і заміни поле ліцензії в кожному файлі пакування.

### Debian і Ubuntu

Потрібні `dpkg-buildpackage`, Debhelper, CMake і GCC:

```bash
sudo apt update
sudo apt install build-essential cmake debhelper devscripts
dpkg-buildpackage -us -uc
sudo apt install ../break-this-repo_0.0.0_$(dpkg --print-architecture).deb
```

Можна також встановити вже зібраний файл `.deb` напряму:

```bash
sudo apt install ./break-this-repo_*.deb
```

### Arch Linux

Потрібні `base-devel`, CMake і GCC. Спершу згенеруй із вихідного коду архів, що відповідає версії в `PKGBUILD`:

```bash
sudo pacman -S --needed base-devel cmake gcc
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o packaging/archlinux/break-this-repo-0.0.0.tar.gz HEAD
cd packaging/archlinux
makepkg -si
```

### Fedora

Потрібні інструменти збірки RPM, CMake і GCC:

```bash
sudo dnf install @development-tools cmake rpmdevtools
rpmdev-setuptree
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o ~/rpmbuild/SOURCES/break-this-repo-0.0.0.tar.gz HEAD
rpmbuild -ba packaging/fedora/break-this-repo.spec
sudo dnf install ~/rpmbuild/RPMS/$(uname -m)/break-this-repo-0.0.0-1.*.rpm
```

### Gentoo

Скопіюй ebuild у локальний overlay, а далі дай Portage згенерувати Manifest і встановити:

```bash
sudo mkdir -p /var/db/repos/local/app-misc/break-this-repo
sudo cp packaging/gentoo/app-misc/break-this-repo/* \
	/var/db/repos/local/app-misc/break-this-repo/
cd /var/db/repos/local/app-misc/break-this-repo
sudo ebuild break-this-repo-0.0.0.ebuild manifest
sudo emerge --ask app-misc/break-this-repo
```

# Debian --універсальна операційна система
[![Debian Logo](https://www.debian.org/Pics/openlogo-50.png)](https://www.debian.org/)
## Debian — це вільне програмне забезпечення.
Debian складається з вільного програмного забезпечення з відкритим кодом і завжди залишатиметься на 100 % вільним. Кожен може вільно використовувати, змінювати й розповсюджувати його. Це наша головна обіцянка користувачам. Воно також безкоштовне.
## Debian — стабільний і безпечний.
Debian — це операційна система на базі Linux, яка використовується на найрізноманітніших пристроях: від ноутбуків до настільних комп'ютерів і серверів. Ми надаємо розумні типові налаштування для кожного пакунка та регулярні оновлення безпеки протягом усього життєвого циклу пакунка.
## Debian має широку підтримку обладнання.
Більшість обладнання вже підтримується ядром Linux. Це означає, що Debian також його підтримує. За потреби можна використовувати й пропрієтарні драйвери обладнання.
## Debian пропонує гнучкий інсталятор.
Користувачі, які хочуть спробувати Debian перед встановленням, можуть скористатися нашим Live CD. Він також містить інсталятор Calamares, що робить встановлення Debian із живої системи дуже простим. Досвідченіші користувачі можуть скористатися інсталятором Debian, який пропонує більше можливостей для тонкого налаштування, зокрема можливість використовувати засоби автоматичного мережевого встановлення.
## Debian пропонує плавні оновлення.
Тримати операційну систему в актуальному стані дуже легко: чи то оновлення до цілком нового випуску, чи оновлення лише одного пакунка.
## Debian — основа багатьох інших дистрибутивів.
Багато дуже популярних дистрибутивів Linux, як-от Ubuntu, Knoppix, PureOS і Tails, базуються на Debian. Ми надаємо всі потрібні інструменти, щоб кожен міг за потреби створити власні пакунки й доповнити ті, яких немає в архіві Debian.
## Проєкт Debian — це спільнота.
Кожен може стати частиною спільноти Debian; не обов'язково бути розробником чи системним адміністратором. Debian має демократичну структуру управління. Оскільки всі члени проєкту Debian мають рівні права, Debian не може контролювати одна компанія. Наші розробники походять із понад 60 країн/регіонів, а сам Debian перекладено понад 80 мовами.

## Шаблон PR
Цей шаблон PR уже не можна назвати шаблоном; його слід називати «Заявка на утримання аномалії для Break-This-Repo».

Ви взяли репозиторій, який лише «автоматично зливає PR без конфліктів», і гралися з ним так довго, що супровідник почав писати:

Тип: стусан у README / стусан у документацію / збій коду порожнього міста / інцидент, спричинений котом / надприродне явище
Перевірка: я не чіпав .github/, не чіпав захищений README, без вірусів, без особистих даних
Заява: я визнаю, що зламав, але причину вигадав, і вона навіть не обов'язкова

По суті це означає: «можеш робити безлад, але не справжній безлад».

Від чого захищає цей шаблон?

Насправді він окреслює межу дуже чітко:

· Не чіпати .github/: заважає комусь підірвати сам процес автоматичного злиття або вставити бекдор у CI.
· Не чіпати захищені частини README: фасад усе ще потрібен, не можна перетворити головну сторінку на щось дивне.
· Без облікових даних, вірусів чи особистих даних: проти атак на ланцюг постачання, проти доксингу, проти справжньої зловмисності.
· Пояснити, як спостерігати: можеш зробити номер, але люди мають знати, як на нього дивитися.
· Заявити «успішний breaking change»: самоіронічна відмова від відповідальності, тобто «я це зробив, але не відповідаю».

Щодо серії «надприродне явище»:

три літери + три стрілки навколо кола + окреслений фонд
карта світу на тлі пентаграми + навколо кільце посівів + міжнародний альянс із п'яти слів
