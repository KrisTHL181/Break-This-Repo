## सोर्स से बिल्ड करें

रिपॉज़िटरी में कई अलग-अलग बिल्ड एंट्री हैं। ज़रूरत के हिसाब से उपयुक्त टूल इंस्टॉल करें और रिपॉज़िटरी की जड़ (root) में कमांड चलाएँ।

### Make के साथ C++

C++11 सपोर्ट करने वाला कंपाइलर चाहिए:

```bash
make
```

बिल्ड के नतीजे साफ़ करने के लिए:

```bash
make clean
```

डिफ़ॉल्ट रूप से `fozu` और `what` बनते हैं; Windows पर `beep_win` भी बनता है।

### CMake के साथ C++

CMake 3.16 या उससे नया, और एक C++ कंपाइलर चाहिए:

```bash
cmake -S . -B build/cmake
cmake --build build/cmake
```

### Meson के साथ C++

Meson, Ninja और एक C++ कंपाइलर चाहिए:

```bash
meson setup build/meson
meson compile -C build/meson
```

### maturin के साथ Python और Rust

Python एक्सटेंशन Rust और [maturin](https://www.maturin.rs/) से बनता है। Rust टूलचेन (`cargo` समेत) और Python 3.13 या उससे नया चाहिए:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install maturin
```

वर्चुअल एनवायरनमेंट के अंदर इनमें से कोई एक कमांड चलाएँ:

```bash
# मौजूदा वर्चुअल एनवायरनमेंट में कंपाइल करके इंस्टॉल करें
maturin develop

# बाँटने लायक wheel फ़ाइल बनाएँ
maturin build --release
```

wheel बिल्ड का नतीजा `target/wheels/` में रहता है। Rust एक्सटेंशन का एंट्री कोड [`src/lib.rs`](src/lib.rs) में है, और Python बिल्ड कॉन्फ़िग [`pyproject.toml`](pyproject.toml) में।

### Hereby के साथ TypeScript

TypeScript वाला हिस्सा `typescript/` में है, और Node.js, npm तथा Hereby इस्तेमाल करता है:

```bash
cd typescript
npm install
npm run build:compiler
```

अगर कंपाइलर और टेस्ट दोनों टारगेट एक साथ बनाने हों तो `npm run build` चलाएँ। बिल्ड के नतीजे साफ़ करने के लिए `npm run clean` चलाएँ।

## Linux डिस्ट्रीब्यूशन पैकेज

डिस्ट्रीब्यूशन पैकेजिंग के टेम्पलेट `debian/` और `packaging/` में हैं। ये पैकेज C++ कमांड-लाइन प्रोग्राम `fozu` और `what` इंस्टॉल करते हैं; Python/Rust एक्सटेंशन के लिए ऊपर बताई गई maturin प्रक्रिया ही इस्तेमाल करें। रिपॉज़िटरी में फ़िलहाल कोई एक जैसा ओपन सोर्स लाइसेंस घोषित नहीं है, तो औपचारिक रिलीज़ से पहले हर पैकेजिंग फ़ाइल का लाइसेंस फ़ील्ड जाँच लें और ठीक कर लें।

### Debian और Ubuntu

`dpkg-buildpackage`, Debhelper, CMake और GCC चाहिए:

```bash
sudo apt update
sudo apt install build-essential cmake debhelper devscripts
dpkg-buildpackage -us -uc
sudo apt install ../break-this-repo_0.0.0_$(dpkg --print-architecture).deb
```

बने हुए `.deb` फ़ाइल को सीधे भी इंस्टॉल कर सकते हैं:

```bash
sudo apt install ./break-this-repo_*.deb
```

### Arch Linux

`base-devel`, CMake और GCC चाहिए। पहले सोर्स से `PKGBUILD` के वर्ज़न से मेल खाती आर्काइव बनाएँ:

```bash
sudo pacman -S --needed base-devel cmake gcc
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o packaging/archlinux/break-this-repo-0.0.0.tar.gz HEAD
cd packaging/archlinux
makepkg -si
```

### Fedora

RPM बिल्ड टूल, CMake और GCC चाहिए:

```bash
sudo dnf install @development-tools cmake rpmdevtools
rpmdev-setuptree
git archive --format=tar.gz --prefix=break-this-repo-0.0.0/ \
	-o ~/rpmbuild/SOURCES/break-this-repo-0.0.0.tar.gz HEAD
rpmbuild -ba packaging/fedora/break-this-repo.spec
sudo dnf install ~/rpmbuild/RPMS/$(uname -m)/break-this-repo-0.0.0-1.*.rpm
```

### Gentoo

ebuild को लोकल overlay में कॉपी करें, फिर Portage से Manifest बनवाकर इंस्टॉल करें:

```bash
sudo mkdir -p /var/db/repos/local/app-misc/break-this-repo
sudo cp packaging/gentoo/app-misc/break-this-repo/* \
	/var/db/repos/local/app-misc/break-this-repo/
cd /var/db/repos/local/app-misc/break-this-repo
sudo ebuild break-this-repo-0.0.0.ebuild manifest
sudo emerge --ask app-misc/break-this-repo
```

# Debian -- सार्वभौमिक ऑपरेटिंग सिस्टम
[![Debian Logo](https://www.debian.org/Pics/openlogo-50.png)](https://www.debian.org/)
## Debian मुक्त सॉफ़्टवेयर है।
Debian मुक्त और ओपन सोर्स सॉफ़्टवेयर से बना है, और हमेशा 100% मुक्त रहेगा। हर किसी को इसे इस्तेमाल करने, बदलने और बाँटने की पूरी आज़ादी है। हमारे उपयोगकर्ताओं से यही हमारा मुख्य वादा है। और हाँ, यह मुफ़्त भी है।
## Debian स्थिर और सुरक्षित है।
Debian एक Linux-आधारित ऑपरेटिंग सिस्टम है जो हर तरह के उपकरणों पर खूब इस्तेमाल होता है — लैपटॉप, डेस्कटॉप से लेकर सर्वर तक। हम हर सॉफ़्टवेयर पैकेज के लिए समझदारी भरा डिफ़ॉल्ट कॉन्फ़िगरेशन देते हैं, और पैकेज के पूरे जीवनकाल में नियमित सुरक्षा अपडेट भी।
## Debian का हार्डवेयर समर्थन बहुत व्यापक है।
ज़्यादातर हार्डवेयर को Linux कर्नेल का समर्थन पहले से मिला हुआ है। यानी Debian भी उन्हें सपोर्ट करेगा। ज़रूरत पड़े तो मालिकाना (proprietary) हार्डवेयर ड्राइवर भी इस्तेमाल किए जा सकते हैं।
## Debian लचीला इंस्टॉलर देता है।
जो लोग इंस्टॉल करने से पहले Debian आज़माना चाहते हैं, वे हमारी Live CD इस्तेमाल कर सकते हैं। इसमें Calamares इंस्टॉलर भी शामिल है, जिससे Live सिस्टम से Debian इंस्टॉल करना बहुत आसान हो जाता है। ज़्यादा तजुर्बेकार लोग Debian इंस्टॉलर इस्तेमाल कर सकते हैं, जो बारीकी से बदलने लायक और भी विकल्प देता है, जिनमें स्वचालित नेटवर्क इंस्टॉल टूल का इस्तेमाल भी शामिल है।
## Debian अपडेट बिना किसी झंझट के देता है।
अपने ऑपरेटिंग सिस्टम को अप-टू-डेट रखना बहुत आसान है — चाहे आप बिल्कुल नए रिलीज़ पर अपग्रेड करना चाहें, या सिर्फ़ एक अकेला पैकेज।
## Debian कई और डिस्ट्रीब्यूशन की बुनियाद है।
बहुत से लोकप्रिय Linux डिस्ट्रीब्यूशन, जैसे Ubuntu, Knoppix, PureOS और Tails, Debian पर ही आधारित हैं। हमने वे सारे टूल मुहैया कराए हैं जिनसे कोई भी ज़रूरत पड़ने पर अपने पैकेज बना सके, ताकि Debian के आर्काइव में न मौजूद सॉफ़्टवेयर भी जोड़ा जा सके।
## Debian प्रोजेक्ट एक समुदाय है।
Debian समुदाय का हिस्सा कोई भी बन सकता है; डेवलपर या सिस्टम एडमिन होना ज़रूरी नहीं। Debian की गवर्नेंस व्यवस्था लोकतांत्रिक है। चूँकि Debian प्रोजेक्ट के सभी सदस्यों के अधिकार बराबर हैं, इसलिए Debian पर किसी एक कंपनी का कंट्रोल नहीं हो सकता। हमारे डेवलपर 60 से ज़्यादा देशों/क्षेत्रों से आते हैं, और Debian खुद भी 80 से ज़्यादा भाषाओं में अनूदित हो चुका है।

## PR टेम्पलेट
अब इस PR टेम्पलेट को टेम्पलेट कहना ही नहीं बनता, इसे "Break-This-Repo असामान्यता निरोध आवेदन-पत्र" कहना चाहिए।

आप लोगों ने "बिना टकराव वाले PR अपने आप मर्ज करने" वाली रिपॉज़िटरी को इतना खेल डाला कि मेंटेनर को लिखना पड़ गया:

प्रकार: README पर लात / डॉक्स पर लात / खोखली-किले जैसी कोड खराबी / बिल्ली से हुई दुर्घटना / अलौकिक घटना
सत्यापन: मैंने .github/ नहीं बदला, सुरक्षित README नहीं बदला, वायरस नहीं है, निजी जानकारी नहीं है
घोषणा: मानता हूँ मैंने तोड़ा है, पर कारण मैंने मन से लिखा है, और वह ज़रूरी भी नहीं

यह असल में यही है: "तोड़फोड़ कर सकते हो, पर सच में तोड़ना मत।"

यह टेम्पलेट किस चीज़ से बचा रहा है?

इसमें लक्ष्मण-रेखा बड़ी साफ़ खींची गई है:

· .github/ मत बदलो: कहीं कोई ऑटो-मर्ज वर्कफ़्लो को ही उड़ा न दे, या CI में पिछला दरवाज़ा न खोल दे।
· README के सुरक्षित हिस्से मत बदलो: दिखने वाला चेहरा तो चाहिए ही, होमपेज को अजीब चीज़ नहीं बनाया जा सकता।
· कोई क्रेडेंशियल, वायरस, निजी जानकारी नहीं: सप्लाई-चेन हमले, डॉक्सिंग और सच में की गई बदनियती — इन सब से बचाव।
· बताओ कि देखेंगे कैसे: तमाशा कर सकते हो, पर लोगों को पता होना चाहिए कि तमाशा देखें कैसे।
· "सफल breaking change हो गया" की घोषणा: खुद पर हँसने वाली डिस्क्लेमर, यानी "मैंने कर दिया, पर ज़िम्मेदारी मेरी नहीं"।

रही "अलौकिक घटना" वाली कड़ी:

तीन अक्षर + गोले में तीन तीर + आउटलाइन वाला फ़ाउंडेशन
पाँच-कोणीय तारे वाला विश्व-नक्शा + चारों ओर फ़सलों का घेरा + पाँच शब्दों वाला अंतरराष्ट्रीय संगठन

पहला SCP फ़ाउंडेशन है, और दूसरा लगभग संयुक्त राष्ट्र खाद्य एवं कृषि संगठन / FAO जैसा कोई अंतरराष्ट्रीय संगठन। अनुवाद करें तो मतलब यह है:
"अब बात कोड की नहीं रही, असामान्यता निरोध संगठन को रिपोर्ट करने की सलाह दी जाती है।"

आपका सबमिशन इस टेम्पलेट में कैसे फ़िट हो सकता है?

आप Minecraft, OpenJDK, Fabric Loader का सोर्स कोड अपलोड करते हो, 4 commits में 1270 लाख से ज़्यादा लाइनें ठोक देते हो, तो प्रकार में टिक लगा सकते हो:

☑ डॉक्स पर लात
☑ खोखली-किले जैसी कोड खराबी (अंबानी की कॉस्प्ले)
☑ Git से क्रॉस-प्लेटफ़ॉर्म
☐ बिल्ली से हुई दुर्घटना
☐ अलौकिक घटना

सत्यापन में सब पर टिक, घोषणा ज्यों की त्यों कॉपी, और कारण बस यह लिख दो:

कारण: मन से लिखा है, ज़रूरी नहीं, पर 12770942 लाइन कोड को तो कोई नाम-रूप मिलना ही चाहिए।

देखने का तरीका:

OpenJDK_25.0.3 खोलो, commit इतिहास देखो, और रिपॉज़िटरी के आकार का सन्नाटा महसूस करो।

पर एक बात याद दिलानी है

ऐसी रिपॉज़िटरी खेल का मैदान है, कानून से बाहर की जगह नहीं। OpenJDK का पूरा सोर्स, Minecraft का सोर्स वगैरह चढ़ाना, भले ही "बिना टकराव ऑटो-मर्ज" भर हो, ये चीज़ें लेकर आता है:

· रिपॉज़िटरी का आकार फट जाता है, GitHub शायद रोक लगा दे या चेतावनी दे;
· कॉपीराइट/लाइसेंस की दिक्कतें, हर सोर्स कोड यूँ ही नहीं ठूँसा जा सकता;
· अगर कोई इस रिपॉज़िटरी को डिपेंडेंसी बना ले, तो सप्लाई-चेन की पूरी आफ़त।

तो नतीजा यह है:
यह PR टेम्पलेट मेंटेनर का "खुलकर तोड़ो" और "सच में धमाका मत होने दो" के बीच का संतुलन है।
तुम लोग खेलते रहो, पर बेहतर होगा कि इसे परफ़ॉर्मेंस आर्ट मानो, कोड रिपॉज़िटरी नहीं। SCP फ़ाउंडेशन वालों को रिपोर्ट मिल चुकी है।

## मौके की बुनियादी ढाँचा पुरातत्व फ़ाइल

![EGIEM-R1 प्रोटोटाइप की असली चीज़: मौके की फ़ोटो](./Emergency-Generator-Interface-Elevation-Module/assets/rock-field-photo.png)

इस रिपॉज़िटरी में अब एक कम बिजली खाने वाली, बेहद भरोसेमंद, बिल्कुल भी इंटरनेट से न जुड़ी मौके की बुनियादी ढाँचा इकाई दर्ज हो चुकी है: एक पत्थर, जिसे ज़रूरत के वक़्त जुगाड़ से ड्यूटी पर बुला लिया गया। इसमें न CPU है, न नेटवर्क कार्ड, और न ही नौकरी छोड़ने का कोई इरादा; यह सिर्फ़ अपने वज़न के दम पर इंटरफ़ेस बॉक्स को सही जगह पर मज़बूती से टिकाए रखता है।

पीला लेबल "एक पत्थर मिला" को "डिवाइस रिकॉर्ड में दर्ज" बना देता है। शुरुआती मूल्यांकन के बाद: इस डिवाइस में लॉगिन नहीं चाहिए, अपडेट नहीं चाहिए, रीबूट नहीं चाहिए, और ज्ञात एकमात्र रखरखाव कार्रवाई यह है: इसे हिलाओ मत।

अपस्ट्रीम डिपेंडेंसी: ऑपरेटर का डीज़ल जनरेटर इंटरफ़ेस बॉक्स
डाउनस्ट्रीम डिपेंडेंसी: पृथ्वी
चालू स्थिति: स्थिर रूप से चल रहा है

फ़ोटो योगदानकर्ता के दिए मौके के ओरिजिनल फ़ोटो से है, सिर्फ़ फ़ाइल का नाम मानकीकृत कर दिया गया, न काटा गया, न दोबारा बनाया गया।
